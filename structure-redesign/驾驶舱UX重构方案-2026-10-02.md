## 一、先说结论：不是"丑"，是**信息架构崩了**

视觉层（2026-09 那次「重构样式 v2」，Linear/Vercel 风）其实不差——
细边框、无斑马纹、小色点 KPI、状态药丸，这套设计语言是对的。

**真正的问题在外壳与 IA**：

| # | 问题 | 实测证据（1440×900） |
|---|---|---|
| **1** | **首屏 80% 是外壳** | 从页面顶端到第一个业务区块要滚 **721px**；首屏 900px 里只有约 180px 是真内容 |
| **2** | **本质是"一条无限长滚动页"** | 展开「更多分析」后 `document.body.scrollHeight = 14011px` ≈ **16 屏**；卡片总高 15783px，32 张卡 |
| **3** | **导航与实际内容不符** | 老板视图 **20 个导航胶囊，但只有 4 个区块可见**（`sec-Today/K/A/PW`）；16 个在折叠区里，点了才展开 |
| **4** | **高频与低频混在同一层** | 「今天要处理」与「导入数据快照 / 重新生成说明 / 同步状况 / 导出分析」并列在同一条按钮带 |
| **5** | **"台账"压过"决策"** | 首屏第 3、4 位是「项目全表」1046px（13 列 40 行）+「思维导图」751px |
| **6** | **sticky 导航遮挡内容** | 滚动后顶部露出被压住的半行文字（`vp-01.png` 顶部） |
| **7** | **同一信息说两遍** | 顶栏「业务表已接入 SeaTable 云端「生产」真实数据（同步于 …）」+ 状态条同句重复 |
| **8** | **移动端横向溢出** | 设 390px 视口，实际 `window.innerWidth = 526px`（被内容撑宽 136px）；导航条内部宽 **1998px** |
| **9** | **KPI 卡没占满宽** | 4 张 KPI 卡只占左半边，右侧大片留白 |

**一句话**：现在这个页面是一本**摊开的活页夹**（22 个区块按顺序铺在一条 16 屏长的纸上），
而不是一个**驾驶舱**（该看什么、该做什么，一屏说完）。

## 二、新架构：6 个一级模块 + 标签页

把 22 个区块重新分组。**区块自身一个都不改**，只改"它们住哪儿"。

| 一级 | 标签页 | 面向的问题 |
|---|---|---|
| **① 今天** | 今天要处理 · 微信情报台 · 消息核对台 | 今早该干什么 |
| **② 项目** | 项目总览&在制 · 项目全表(40) · 成本分析 | 合同 / 收款 / 毛利 |
| **③ 在产** | 甘特图(35) · 生产计划全表(36) · 产线流转 · 工时分析 · 资源负载 | 货在哪儿、卡在哪 |
| **④ 供应** | 供应链(采购) · 库存预警 · 物料行情 · 原料行情 | 买什么、贵不贵 |
| **⑤ 质量** | 质量分析 · 更多指标 | 良品率 / 维修 / 交期达成 |
| **⑥ 分析** | 风险雷达 · 思维导图 | 倒排 / 画像 / 预测 |
| **全局动作** | 新建（项目/生产计划）· 补录数据 | 收进顶栏 |

**分组依据**：按**"问题"**分，不按**"表"**分。原来「工时/成本/质量/供应链」四维被拆散——
成本归"项目"（合同额、实收、成本、毛利讲的是同一笔钱），工时归"在产"（它衡量的是产能），
供应链单独成模块（它有自己的上游节奏）。

## 三、外壳设计

### 桌面（≥1024px）

```
┌──────────────────────────────────────────────────────────────────────┐
│ ▣ 生产驾驶舱    ● 数据 10-01 19:08    [生产经理 ▾]      [＋新建] [⋯] │ 56px 固定
├────────────┬─────────────────────────────────────────────────────────┤
│ ● 今天   3 │  在产 ▸ 甘特图                                          │
│   项目     │  ┌───────────────────────────────────────────────────┐ │
│   在产     │  │                                                   │ │
│   供应  2  │  │              内容区（每个标签页 1~2 屏）            │ │
│   质量     │  │                                                   │ │
│   分析     │  └───────────────────────────────────────────────────┘ │
│            │                                                          │
│ ──────     │                                                          │
│ 数据源 ✓   │                                                          │
└────────────┴─────────────────────────────────────────────────────────┘
   168px
```

- **顶栏 56px，单行**。运维动作（导出分析 / 导出快照 / 导入快照 / 重新生成说明 / 同步状况）
  全部收进 `⋯` 菜单。数据时间做成一个 `● 10-01 19:08` 状态点，点开才展开详情。
- **左侧 168px 固定导航**，带角标（今天 3 条待办 / 供应 2 条逾期）。
- **内容区顶部一条标签页**，不再有"滚动锚点"。
- **sticky 只用在标签页**，且内容区加 `scroll-margin-top` 修掉遮挡。

### 移动（<1024px）

```
┌───────────────────────┐
│ ☰  今天            ⋯ │ 56px
├───────────────────────┤
│ [全部][微信][核对]    │ 标签横滚
│                       │
│      内容             │
│                       │
├───────────────────────┤
│ 今天 项目 在产 供应 … │ 底部标签栏 56px
└───────────────────────┘
```

移动端把左侧导航换成**底部标签栏**（原生 App 手感），一级模块 6 个正好放得下。

## 四、视觉层要改的四处

1. **表格**：表头 `position:sticky`；日期列 `white-space:nowrap`（原来 `2026-07-28` 会竖着断成两行）
2. **KPI 卡**：`grid-template-columns: repeat(auto-fit, minmax(200px, 1fr))` 铺满宽度
3. **间距**：`--gap` 统一 16px；卡片间距从 20px 收到 16px，同屏多放一条
4. **状态色**：沿用；但「剩余（天）」负数不再只染红——加"已逾期 N 天"文案，数字本身不做唯一信号

## 五、实施策略：**换壳，不动心脏**

```
cockpit/cockpit.py
├── 1-1375    数据层（compute + 加载器）      ← ✅ 一行不动
├── 1376-4085 HTML 模板
│   ├── <style>       ← 🔧 追加外壳 CSS（旧样式保留，区块复用）
│   ├── <body> 标记   ← 🔧 换成新外壳（topbar / sidenav / tabbar）
│   └── JS
│       ├── 区块渲染器（22 个）  ← ✅ 一个不动
│       ├── put(key,node) 挂载   ← 🔧 改成挂进「标签面板」
│       └── ROLES / SEC_NAV      ← 🔧 换成 MODULES 分组
└── 4086+     main()                ← 🔧 加 --legacy-ui 回退
```

**为什么能这么省**：原代码所有区块都通过统一的 `put(key, node)` 挂载，
`put` 里只判断"进首屏还是进折叠区"。把它改成"进哪个标签面板"，
22 个区块的渲染代码**零改动**。

**回退**：`python cockpit/cockpit.py --legacy-ui` 生成旧版；或 `git checkout cockpit/cockpit.py`。

### 与最初目标的偏差（如实记录）

我一开始把「首屏业务内容 ≤ 120px」定为目标，**实际做到 198px，没有达标**。差在 KPI 条：
它吃掉 42px + 12px 上边距。之所以保留，是因为那 4 个数字（在制单数/交期达成率/在产缺料/
平均生产周期）是这台"驾驶舱"的体检表，每个标签页都看得到比省 54px 更值。
**如果要去掉这 54px，只需把 `#kpiBar` 改挂到「今天」页内部即可**——但那样其他 5 个模块就看不到体检表了。

**未做的一项**：表格表头吸顶。原因是现有表格外层都是 `<div style="overflow-x:auto">`，
按 CSS 规范一轴非 `visible` 时另一轴会算成 `auto` —— 那个 div 因此成了纵向滚动容器，
`position:sticky` 以它为基准偏移，表头会钉在表格正中间压住第 5 行（第一版实测截图可见）。
现有表格都 `data-paginate` 到 8 行/页，本来也不需要吸顶，故直接放弃。
若将来确实要吸顶，需把包裹层改成 `max-height + overflow:auto` 的自滚动数据网格。

## 七、实施过程中踩到并修掉的 4 个坑（都写进代码注释了）

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | 整页 JS 全废（`Unexpected identifier 'svg'`） | 图标占位符写进了 `icon:"__IC_NEXT__"`，Python 替换进来的是带双引号的 `<svg class="...">`，把 JS 字符串提前截断 | 改成反引号 `` icon:`__IC_NEXT__` `` |
| 2 | 移动端 `innerWidth=570`（旧版也有，526） | 顶栏数据 chip 里塞了整句「真实数据 · 较新 · 同步于 2026-10-01 19:08:08 · 22 小时前」且 `nowrap`，把 layout viewport 顶宽 | CSS 夹住 `max-width:min(360px,44vw)` + 窄屏只显示「数据源 · 新鲜度」，时间戳移入 `title` |
| 3 | 表头钉在表格中间压住第 5 行 | 见上节（`overflow-x:auto` 包裹层的 sticky 基准问题） | 放弃 sticky 表头 |
| 4 | 导航角标显示「今天 78」 | 把「3 条紧急待办 + 70 条微信积压 + 5 条待核对」加成了一个数 | 角标只算今日紧急项；积压归到各自标签页的角标上 |

另外顺手修掉的旧问题：
- **「补录缺失数据」区块（`secBF`）此前从未被渲染过** —— 它的 key `BF` 不在任何角色的 `sections` 里，
  `put()` 一直把它丢掉。现在挂进抽屉（仅生产经理/销售），这个功能第一次真正可用。
- 「数据快照…业务表已接入 SeaTable 云端…」同一句话在顶栏和状态条说了两遍 → 合并到 chip + 详情弹窗。
- `.wrap` 旧容器与 `header.top` 四行堆叠结构整体废弃。

# 附录：v7 图表层（同日追加，2026-10-02 晚）

## A. 先做研究，再动手（4 次检索）

不自己拍脑袋定审美。查到的**可引用依据**：

| 来源 | 关键结论（直接决定了下文的做法） |
|---|---|
| 中国 MES / 制造业看板通行规范 | 核心 KPI 置顶；**绿/黄/红三档语义色**（达成率 ≥90 绿、良率 ≥98 绿、OEE ≥75 绿）；实际值**必须配目标值**；每屏 6~8 个组件封顶；同一屏图表类型 **≤4 种**；「3 秒扫读」「5 秒法则」 |
| Tremor（React 图表组件库） | KPI 卡解剖＝`标签 + 大数字 + BadgeDelta 环比角标 + ProgressBar + SparkChart`；`DeltaType` 枚举（increase / moderateDecrease / unchanged…） |
| shadcn `dashboard-01` | 页面结构＝`SidebarProvider + AppSidebar(inset) + SiteHeader + section-cards(4 张 KPI 卡，container query) + chart-area-interactive + data-table`；KPI 卡就是 4 张，不贪多 |
| 开源 OEE 看板 `Uyadav207/Dashboard-OEE` | 主指标按阈值配色；**Top 3 停机原因 + 时长**；**Pareto 分析**；迷你柱图；环比涨跌箭头 |

**最有用的一句原话**：
> *"a count of 47 parts means nothing without knowing the target was 60."*

这句话解释了 v6 为什么"数字都有、还是不像驾驶舱"——**所有 KPI 都是裸数字，没有基准**。
所以 v7 的硬要求是：**每个 KPI 必须带目标值或历史基准**，否则不许上卡。

## B. 硬前提没破：仍然是单文件离线

本驾驶舱要能**发微信、断网打开**，所以**不能引任何 CDN 图表库**。
解法：**用 CSS 布局 + 内联 SVG 自己画**。够用的只有 4 种图，正好卡在规范建议的
「同一屏图表类型 ≤4 种」以内：

| 图形 | 用途 | 实现 |
|---|---|---|
| **横条榜** `barList()` | Pareto（缺料 Top / 应收 Top / 供应商延迟 / 原料波动 / 生产周期） | 标签 + 值 + 条，三行网格 |
| **构成条** `stackBar()` | 成本结构 / 项目状态 / 在制阶段 | 单条 flex + 图例，**替代饼图**（长度比角度好读一个量级） |
| **迷你走势** `spark()` | 月度合同额 / 月度工期 / 月度计划量 | 内联 SVG `path`，`preserveAspectRatio=none` 拉伸 + `non-scaling-stroke` 保线宽 |
| **良率环** `ring()` | 贴片 / 组装良品率、维修率 | SVG `stroke-dasharray` |
| **子弹图** `bullet()` | 实际 vs 目标（交期达成率、甘特健康度） | 填充条 + 目标刻度线 |

配套三个格式化器：`statCard()`（KPI 卡）、`trendPill()`（环比角标）、`vizCard()`（图表卡外壳）。

**语义阈值表 `THRESH` 集中在代码一处**，业主想改口径只动这张表：

```javascript
const THRESH={
  ontime_rate:[90,80], exec_rate:[80,50], smt_yield:[98,95], asm_yield:[98,95],
  margin:[25,10], kit_rate:[98,90],
  repair_rate:[2,5], purchase_overdue:[0,2], shortage:[0,2], res_over:[0,1], zero_stock:[0,3],
  sup_delay:[3,7], res_load:[85,100],
};
```

## C. ★ 顺手查出并修掉 3 个**真 bug**（都不是样式问题，是会误导决策的数据问题）

| # | 症状 | 根因 | 修法 | 修后 |
|---|---|---|---|---|
| **1** | **贴片良品率长期显示 30.4%** | 13 条贴片记录里有 2 条只填了「贴片数量」（3000 / 1000）**没填「良品数量」**，旧算法把这两条的投入照样计进**分母** | 分母只统计「良品数量已录」的行；剔除量暴露给前端 | **94.4%**（11/13 批），卡片上标注「2 批待补录 · 合计投入 4000 片已从分母剔除」 |
| **2** | **「供应商准时率」恒为 0%** | 该 KPI 读 `supply.supplier`，而**真实库里那张表是空的** → 把「没有样本」谎报成「准时率为零」 | 改读 `foresee.supplier` 的 106 个真实历史样本，算**到货延迟天数**；无样本时显示 `—` 并注明「待补录到货日期」 | **7.6 天**（加权），并新增两图：各品类延迟 + 最差品类「组装料」供应商排行 |
| **3** | **物料齐套率显示 `93.5064935064935%`** | `pct()` 旧实现是裸的 `n+"%"`，任何未预先 round 的比值都会把十几位小数原样上屏 | `pct()` 内置 `Math.round(v*10)/10` 作为**全局兜底**（调用方 round 过是双保险，漏了也漏不到界面） | **93.5%**；全 5 角色 × 全部 KPI 扫描确认无裸露小数 |

> 这三个和 v6 修掉的「导航角标把 70 条积压算成今日待办」是**同一类 bug**：
> **脏数据污染聚合，产出一个看着像真的假指标。** 判据可以固化为一句：
> **分子有数、分母缺数的行，必须整行剔除，并把剔除量显示出来。**

另外补了一个**复合指标的染色错误**：`statCard` 原先只有 `sev` 一个严重度，
于是「在制单数 9」因为"其中有 5 单逾期"被整张卡染红 —— **9 这个数字本身是中性的**，
染红等于谎报。改为 `sev`（圆点＝要不要看）+ `nsev`（数字＝自身好不好）双通道。

## D. 同时修掉 3 个**既有布局缺陷**（v7 加图表后暴露出来）

| 症状 | 根因 | 修法 |
|---|---|---|
| 质量页良率卡被挤成窄条，三列宽度不均 | `.g2/.g3` 用的 `1fr` 实为 `minmax(auto,1fr)`，列里有**长不可断内容**（维修明细单元格塞了 markdown 原文表格）就会撑开整行 | `.grid.g2/.g3` → `minmax(0,1fr)` |
| 移动端 KPI 退回「1 列 4 行」，把首屏内容全挤到折叠线以下 | v6 在 `@media(max-width:600px)` 里写的 `#kpiBar{grid-template-columns:1fr 1fr}` **写在 v7 新网格规则之前**，同优先级后者胜出 | 媒体查询移到 v7 规则之后，并同步收窄卡内字号（181px 宽下不缩会把大数字挤成两行） |
| 「更多指标」横滚条里的统计卡被压扁 | `.hscroll>.card, .hscroll>.kpi` 的弹性尺寸规则覆盖不到新类名 `.stat` | 补 `.hscroll>.stat{flex:0 0 auto;min-width:210px;max-width:276px}` |

还有一个 SVG 细节：`preserveAspectRatio="none"` 会把迷你走势的**末点圆形拉成椭圆**
（`vector-effect` 只管描边宽度、救不了圆的形变），改用**竖线 path** 作末点标记。
