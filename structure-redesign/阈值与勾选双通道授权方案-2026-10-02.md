## 一、先纠正一个事实：驾驶舱**目前没有勾选功能**

`cockpit/cockpit.py` 的核对引擎段写着（原话）：

> 铁律：核对引擎只读不写库——高置信项仅生成「预填意图」，人确认后才落 SeaTable。
> **驾驶舱只做展示与指引，不提供任何直接写库按钮。**

现在驾驶舱对核对项只做三件事：**列表展示、按置信度排序、给"下一步行动"建议**。没有勾选框。

**但你要的通道已经存在，只是没接上——它叫「补录回传」。**

## 二、好消息：「补录回传」就是现成的 Web 回写通道

`cockpit.py` 里的机制（已实现）：

```
① Web 端填写   <input data-tbl="生产计划" data-rid="..." data-field="计划开始日期">
② 存本地       localStorage["cockpit_backfill_v1"]（刷新不丢）
③ 在线模式     liveAPI("/api/backfill") → 存到本机 data/补录回传.csv
              → 提示「跟我说『处理补录回传』即可确认写入 SeaTable」
   （离线模式则复制 JSON 粘给我）
④ 人确认       我读 CSV → 经 DataService 写库
```

**现在它只用在两类补录上**：`生产计划` 的三个日期字段、`组装记录.组装良品率`。

**★ 把它扩展到「核对项勾选」，零新架构。**

## 三、你的两个通道，我建议**都做，但分工**

### 通道 ①（主）：驾驶舱勾选 —— 每天早上一轮，3 分钟

在核对项区加勾选框，复用补录回传：

```
核对项            置信   建议动作            勾选
到货 · ⟨贴片厂A⟩     92分   状态→已到货          [✓]
到货 · ⟨供应商A⟩       88分   状态→已到货          [✓]
下单 · ⟨芯片供应商A⟩     71分   需确认单号           [ ]
贴片完成 · ⟨组装厂A⟩    90分   更新贴片记录 + 工序    [✓]
```

- 高置信**默认勾选**，你扫一眼、取消误勾的、点「提交」
- 提交 → `/api/backfill` → `data/补录回传.csv`
- 你说「处理补录回传」→ 批量经 DataService 写库（**幂等键 + 读回验证 + 台账**）

### 通道 ②（辅）：置信阈值自动 —— 只放行"零歧义"的

**但阈值不能是一把尺子。** 不同事件的风险差了几个量级：

| 事件 | 会改什么 | 建议自动阈值 |
|---|---|---|
| 到货时间戳 | `到货时间` 一个日期 | **≥ 85 自动** |
| 贴片完成 / 组装上线 | 记录日期 + **工序进度** | **≥ 85 自动** |
| 状态推进（→已到货 / 贴片中） | 驱动 KPI、驾驶舱、风险雷达 | **≥ 95 自动** |
| **下单** | 状态 + 下单时间（**涉及金额**） | **永不自动**，必须勾选 |
| **收款** | 实收金额（**涉及钱**） | **永不自动** |
| **缺料** | 只告警 + 标记卡住，**不改状态** | 自动（无副作用） |

**这就是你说的"高置信不等于授权"的正确用法**：不是用一个阈值卡所有事，而是
**按「事件类型 × 置信分」双维决定** —— 事实时间戳可以松，钱和 KPI 必须紧。

## 四、置信度要从「三档」升级为「分数」

现状：`wxmatch._mk(..., conf)` 传的是**字符串**「高/中/低」，无法设阈值。

**升级方案（保留标签做展示，分数做阈值）：**

```
供应商名精确命中            +40
来源群即该供应商专属群       +15    ← 群名直接映射（实测可行）
该供应商在途记录唯一         +25
物料 / 型号命中             +20
数量吻合                    +10
日期落在交期 ±7 天内          +5
────────────────────────────────
≥90 极高   75~89 高   55~74 中   <55 低
```

**实测依据**（群名可直接映射供应商/加工厂，这是最稳的一条信号）：

| `⟨客户F⟩-⟨组装厂A⟩加工沟通群` | ⟨组装厂A⟩ | `组装记录.组装厂` |

## 五、每天早上的完整工作流

```
09:00  自动化：同步微信 → 生成核对项（带置信分）
          ↓
       分数 ≥ 阈值 → 自动写入（进台账，标记「已自动」）
       其余 → 进驾驶舱待勾选队列
          ↓
09:05  你打开驾驶舱「微信核对台」：
         · 顶部一行「今日已自动写入 4 条 · 查看 · 撤销」
         · 下面列出待勾选项，高置信默认打勾
         · 扫一眼、取消误勾、点「提交」
          ↓
09:08  你说一句「处理补录回传」→ 批量写库（幂等 + 读回验证 + 台账）
          ↓
        自动写入的项目同步推进「产品工序」进度 → 甘特图更新
```

**★ 必须同时做「撤销」**：自动写入的每一条都进台账，驾驶舱上给「撤销」按钮
（走同一条补录回传通道，提交 `状态=撤销` → 我按台账回滚原值）。
**没有撤销的全自动是不可接受的**——这是你「高置信≠授权」原则的技术兑现。
