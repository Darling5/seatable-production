## 一、这张甘特图证明了什么

它不是一个"排期表"，它是一条**产品从开工到可出货的完整工序路径**：

```
生产计划                                    ← 一个项目产品
 ├ 库存核对          1 个工作日
 ├ PCB下单          13 个工作日
 ├ 物料采购         20 个工作日  [汇总]
 │   ├ IC采购        18 个工作日
 │   └ 4G模组烧录      2 个工作日
 └ 外壳组装料        10 个工作日  [汇总]
     ├ 组装料采购     10 个工作日
     ├ 外壳采购      10 个工作日
     ├ 贴片          5 个工作日
     ├ 贴片完成       0 个工作日   ← 里程碑
     ├ 组装          3 个工作日
     └ 组装完成       0 个工作日   ← 里程碑
```

**对应的表，Base 里全都有：**

| 甘特图任务 | Base 里的表 | 现挂载 |
|---|---|---|
| 库存核对 | `库存核对记录` | 5 行 / 3 挂上 |
| PCB下单 | `PCB下单记录` | 3 行 / 2 挂上 |
| IC采购 | `IC采购记录` | 71 行 / 49 挂上 |
| 4G模组烧录 | **（无表）** | — |
| 组装料采购 | `组装料采购记录` | 38 行 / 27 挂上 |
| 外壳采购 | `外壳采购记录` | 5 行 / 3 挂上 |
| 贴片 | `贴片生产记录` | 13 行 / 11 挂上 |
| 组装 | `组装记录` | 6 行 / 2 挂上 |
| （成品采购） | `成品采购记录` | 28 行 / 17 挂上 |
| （PCBA半成品） | `PCBA半成品采购记录` | 7 行 / 3 挂上 |

**结论：缺的不是表，是「把表和产品串起来的那一层」。**

## 二、★ 架构早就设计好了，只是没接上

这是我前两版都漏掉的地方：

### `生产工序` 表 = 工序字典（15 行，已存在）

| # | 工序 | 被几个生产计划引用 |
|---|---|---|
| 1 | `01 库存核对` | 2 |
| 2 | `02 PCB下单` | 2 |
| 3 | `03 外壳采购` | 1 |
| 4 | `04 贴片料采购` | 13 |
| 5 | `04T 模组烧录固件` | 5 |
| 6 | `05 组装料采购` | 6 |
| 7 | `05T PCBA半成品采购` | 3 |
| 8 | `06 贴片` | 2 |
| 9 | `06T开钢网` | 1 |
| 10 | `07 PCBA综测` | 8 |
| 11 | `08 组装` | 2（**有子流程**：器件装壳/按键测试/喇叭测试/振动测试/高度校准/打胶封壳） |
| 12 | `08T成品采购` | 9 |
| 13 | `09测试` | 2 |
| 14 | `10配置IP端口` | 6 |
| 15 | `11 出货` | 2 |

### `工时记录` 表 = 空的工序实例骨架（**0 行**）

```
操作人员 · 关联生产计划(LINK) · 关联工序(LINK) · 开始时间 · 结束时间
         · 实际耗时（小时）· 良品数量 · 异常说明 · 备注
```

**这两张表合起来，正是甘特图需要的结构。** 而且 `生产计划.工序` ↔ `生产工序.生产计划` 双向**完全一致**（64 = 64 条配对），链路本身是健康的。

### 问题在于：它是「打标签」，不是「走流程」

| 实测 | 结果 |
|---|---|
| 36 个生产计划挂了几道工序 | 平均 **1.8 道**；挂 1 道的占 15 个 |
| **一道工序都没挂的生产计划** | **8 / 36** |
| `工时记录`（工序实例表） | **0 行，从未启用** |
| 甘特图显示一个产品要走 | **10+ 道工序** |

→ **工序目前只是"字典里的名词"，不是"每个产品走一遍的实例"。所以进度只能到产品级，画不出甘特图。**

## 三、整个架构的病灶：三处「没接上」

| # | 缺的层 | 证据 | 后果 |
|---|---|---|---|
| 1 | **项目产品** | `项目.产品需求` 一个格子压 **101 个产品** | 产品没有实体，一切都挂不上 |
| 2 | **产品工序（实例）** | 字典 15 行、实例表 0 行、8/36 产品没挂工序 | 进度到不了工序级，画不出甘特图 |
| 3 | **单据行** | 10 处压格，**645 个明细行** | 采购/发货明细查不了、算不了 |

**旁证（数据在漂）**：采购/生产记录挂到产品的比例只有 **33%~85%**，
`组装记录` 6 行里只有 2 行挂上了、`PCBA半成品采购记录` 7 行只有 3 行。

## 四、v3 目标架构

```
① 项目（40）              合同 / 收款 / 交期 / 客户
        ↓
② 项目产品（101）          一行一个产品 = 要交付的东西
   ← 由「生产计划」表升格：补上需求面字段（产品名称/型号/数量/单价/金额/交付状态）
        ↓
③ 产品工序（N 行）★ 核心  一行一道工序 = 这个产品的生产进度主线
   ← 启用并改造「工时记录」表（现成骨架，0 行）
        · 关联项目产品      link → ②
        · 关联工序          link → 生产工序字典（15 行）
        · 序号（01~11）     用于排序与甘特顺序
        · 状态              未开始 / 进行中 / 已完成 / 卡住
        · 计划开始 · 计划完成 · 实际开始 · 实际完成   ← **甘特图数据源**
        · 是否里程碑
        · 执行记录          link → ④ 中对应的那一行
        ↓
④ 执行记录（10 张，已存在）
   IC采购 / PCB下单 / 外壳采购 / 组装料采购 / PCBA半成品采购
   贴片生产 / 组装 / 成品采购 / 库存核对 / （新增）模组烧录
        ↓
⑤ 记录明细行（645 行）     拆格子：一行一个物料/物品
```

**统一挂载规则（这就是"表格间的关系"）：**

| 事实 | 挂到哪 |
|---|---|
| 这个产品要多少、多少钱 | `项目产品` |
| 这个产品走到第几道工序、什么时候 | **`产品工序`** |
| 这道工序买了什么料 | 执行记录 → `产品工序` |
| 每个料多少钱 | 明细行 → 执行记录 |

**建议给 `生产工序` 字典加一列 `执行记录表`（text/single-select）**，标明每道工序由哪张表承接 ——
这样系统才能自动把记录挂到正确的工序上，而不是靠人记。

## 五、甘特图怎么落进 SeaTable

| 甘特图元素 | SeaTable 落地 | 可行性 |
|---|---|---|
| 任务行 | `产品工序` 表一行 | ✅ |
| 任务名称 | link → `生产工序.当前流程` | ✅ |
| 工期（工作日） | `工期` number（字典给默认值） | ✅ |
| 开始 / 完成日期 | `计划开始`/`计划完成`（另有实际日期） | ✅ |
| 汇总任务（物料采购、外壳组装料） | `分组` 字段 或 父工序 link | ✅ |
| 里程碑（0 工作日） | `是否里程碑` 勾选 | ✅ |
| **依赖箭头** | ⚠️ **SeaTable 不支持任务依赖**，用 `前置工序` link 表达 | 部分 |
| **关键路径（红色）** | ⚠️ 不支持自动计算，可加 `关键路径` 勾选人工标记 | 部分 |
| **甘特图本身** | ✅ **App Builder 的 Timeline 页面 / 时间线视图** | ✅ |
| 工作日计算（跳过周末） | ⚠️ 用公式或脚本 | 部分 |

**明确的能力边界**：SeaTable 能画出这个甘特图（时间线视图，按 `项目产品` 过滤就是一个产品的完整路径），
但**依赖推导和关键路径计算它做不了** —— 这部分要么人工维护，要么继续留在 MS Project。
