# SeaTable 项目录入结构改造方案

> 提出时间：2026-10-02 · 状态：**待业主拍板** · 本方案**未对任何数据做改动**
> 依据：全部来自对生产库的**只读实测**（18 张表 / 40 项目 / 36 生产计划 / 85 产品行）

---

## 一句话结论

把「产品」从项目表的一个**长文本格子**（Markdown 表格）提升为**独立的一行** ——
新建 `项目产品` 表，一行 = 一个项目里的一个产品，用关联列向上挂回项目、向下挂生产计划。
项目表原 `产品需求` 列**原地保留不动**（退化为档案），因此**零数据损失、零既有代码路径中断**。

---

## 一、现状诊断：为什么现在的结构撑不住

### 1.1 粒度错位是根因

| 表 | 一行代表什么 | 行数 | 产品信息存在哪 |
|---|---|---|---|
| `项目` | 一个项目 | 40 | `产品需求` 列 —— **一整块 long-text，Markdown 表格，含 1~7 个产品** |
| `生产计划` | 一个生产批次 | 36 | `生产产品` 列 —— 文本 |

**同一个业务概念（产品）在两张表里的粒度完全不同**，于是只能在项目级硬挂关联：

- `项目.生产计划` 关联列挂的是**项目级的计划集合**，无法表达「这条计划对应的是本项目里的哪个产品」
- 数量对不上：**85 个产品行** vs **33 条挂了项目的计划** → 大量产品**没有落点**
- 实测：40 个项目里 **15 个项目 0 条计划**；产品行 87 条中仅 22 条（25%）能与计划按数量对上

这就是原话说的「**一行里面一堆项目产品扎堆只能对应一个生产产品的计划**」。

### 1.2 三个已经发生的后果（实测数据）

**① 产品没有落点** —— 15 个项目一个计划都没挂，包括有 6 个产品的项目：

```
⟨项目12⟩  ⟨客户A⟩-人员定位系统      产品行 6  →  计划 0
⟨项目08⟩  ⟨客户B⟩-人员定位系统      产品行 2  →  计划 0
⟨项目11⟩  ⟨客户C⟩20PCBA 测试新模具     产品行 2  →  计划 0
...
```

**② 一条计划盖多个产品，反过来一个项目多条计划也说不清** —— 真堆行 1 条：

```
⟨项目06⟩  数量=138   「UWB信标 ⟨型号A⟩ ×136；UWB网关 ×2」   ← 1 行塞了 2 个产品
```

**③ 双套关联并存，且各有独有数据** —— 项目 ↔ 生产计划 之间存在**两条**关联：

| 链路 | link_id | 项目侧列名 | 计划侧列名 | 配对数 | 状态 |
|---|---|---|---|---|---|
| 组 A | `3Fld` | 项目.生产计划 | 生产计划.关联项目 | 35 | 在用（计划侧那列**未隐藏**） |
| 组 B | `wana` | 项目.**阶段** | 生产计划.项目 | 22 | 项目侧列名错叫「阶段」；计划侧那列**已隐藏** |

⚠️ **两组不是包含关系** —— 有 **4 对配对只存在于组 B**：

```
项目「⟨客户E⟩」                    → 计划 ⟨客户D⟩-4GUWB小卡
项目「⟨客户C⟩-人员定位系统(DW…)」    → 计划 ⟨客户A⟩小卡60张4G小卡全功能
项目「⟨客户C⟩防爆+3C认证（⟨客户F⟩）」    → 计划 3个UWB信标+10组电池
项目「⟨客户C⟩（山东）-UWB定位工卡及信标」→ 计划 UWB信标 ⟨型号A⟩（有线供电，防爆格兰头）
```

**任何「只取一条链路」的迁移都会丢掉这 4 条。**

### 1.3 `产品需求` 的真实形态（决定迁移工作量）

| 指标 | 实测值 |
|---|---|
| 表头形态 | **12 种**，但同族清晰（名称/型号/数量/单位/单价/金额 ± 交付状态 ± 序号） |
| 可解析产品行 | **85 条**（覆盖 35/40 项目） |
| 解析异常 | **17 条**：合计行 13（应丢弃）、疑似备注 2、产品名为空 1、**整个格子无表格 1**（⟨项目02⟩ ⟨客户G⟩） |
| 「表外文字」 | 我上一轮的判断**需要修正**：40 个项目里 31 个有表外文字，但绝大多数只是一个 `###### 需求` 标题或零宽字符 `\u200b`，**几乎不含信息** |
| 数量列带单位 | 5 行（`25张` `16台` `1套` `1项` `6 KG`）需拆分 |
| 「交付状态」列 | **不能做单选项** —— 实测有 `√`、`出货20+67+246=333张差867`、`肖总上报了窄带卡的原理图` 这种自由文本 |

### 1.4 视图面的影响很小（好消息）

两张表**各只有 1 个「默认视图」**，改造不涉及多视图维护：

| 表 | 视图 | 分组 | 排序 | 隐藏列 |
|---|---|---|---|---|
| 项目 | 默认视图（仅此一个） | 状态 | 项目编号 ↓ | 无 |
| 生产计划 | 默认视图（仅此一个） | 状态 | 计划开始日期 ↑ | 12 列（含 `项目`、`工时记录` 等） |

## 二、目标结构

你要的是**三层、以项目为分组、产品各占一行、每行挂自己的计划**：

```
项目 ⟨项目01⟩  ⟨客户D⟩（⟨客户F⟩）          ← 分组头（项目表一行）
 ├─ 产品行 ①  UWB信标      ⟨型号A⟩   195  →  生产计划 2026xxxx-001
 ├─ 产品行 ②  蓝牙信标       ⟨型号B⟩    100  →  生产计划 2026xxxx-002
 └─ 产品行 ③  人员定位系统    ⟨型号C⟩   1  →  （待排产）
```

关键变化：**`产品` 成为一等业务对象**（有行、有 id、有关联），而不是一段文本。

## 三、推荐方案 A：新建 `项目产品` 表

### 3.1 新表设计（19 列）

| 列名 | 类型 | 说明 |
|---|---|---|
| `产品编号` | auto-number | 行标识（SeaTable 自动，不可指定） |
| `产品名称` | text | **必填**，来自 `产品名称`/`商品名称` |
| `型号` | text | 来自 `型号`/`规格型号`（填充率 91%） |
| `数量` | number | 来自 `数量`（填充率 100%，需先剥离单位） |
| `单位` | text | 来自 `单位`（填充率 35%，缺失留空） |
| `单价` | number | 来自 `单价`/`单价（元）`（79%） |
| `金额` | number | 来自 `金额`/`金额（元）`/`小计（元）`（64%） |
| `交付备注` | **long-text** | ⚠️ 来自 `交付状态`/`状态` —— **必须用长文本**，因为实测取值是自由文本（`√` / `已交付` / `出货20+67+246=333张差867`）。**不要建成单选** |
| `交期` | date | 仅 2 行有值（`⟨项目10⟩` `⟨项目13⟩` 的表头里第 6 列是交期而非金额） |
| `备注` | text | 预留（现状 0 行有值） |
| `所属项目` | **link → 项目** | 向上挂。SeaTable 会在 `项目` 表自动生成反向列 `项目产品` |
| `生产计划` | **link → 生产计划** | 向下挂。会在 `生产计划` 表自动生成反向列 `项目产品` |
| `来源` | text | 迁移溯源，写 `产品需求@<项目编号>` 或 `人工录入` |
| `数据质量` | single-select | `正常` / `待确认` —— 迁移时把异常行标出来，**不丢弃** |

> **为什么不用 single-select 存交付状态**：现状 13 种取值里 9 种是自由文本（含 `出货20+67+246=333张差867`）。
> 强行收窄成选项 = 在迁移中**丢信息**，这是本项目最忌讳的。

### 3.2 关联设计（三条链路并存，互不破坏）

| 链路 | link_id | 用途 | 动作 |
|---|---|---|---|
| 项目 ↔ 生产计划（组 A `3Fld`） | 现有 | 项目级兜底：「这个项目一共排了哪些批次」 | **不动** |
| 项目 ↔ 生产计划（组 B `wana`） | 现有 | 历史链路，有 4 对独有数据 | **不动、不删**；迁移时把 4 对补进 `项目产品` |
| **项目产品 ↔ 项目** | 新建 | 分组主链路 | 新建 |
| **项目产品 ↔ 生产计划** | 新建 | 产品级计划落点 | 新建 |

### 3.3 迁移映射（产品需求 → 项目产品）

**按表头名字映射，不按列位置**（12 种表头的列序不同）：

| 源表头 | 目标列 | 处理 |
|---|---|---|
| `产品名称` / `商品名称` | 产品名称 | 直取；命中 `合计`/`小计` 的**整行丢弃**（13 行） |
| `型号` / `规格型号` | 型号 | 直取 |
| `数量` | 数量 | 剥离单位：`25张`→`25` + 单位`张` |
| `单位` | 单位 | 直取 |
| `单价` / `单价（元）` | 单价 | 去千分位逗号 |
| `金额` / `金额（元）` / `小计（元）` | 金额 | 去千分位逗号 |
| `交付状态` / `状态` | 交付备注 | 直取（**不强转枚举**） |
| `交期` | 交期 | 直取 |
| `备注` | 备注 | 直取 |
| `序号` | —— | 丢弃 |
| 图片 `![](...)` | —— | 剥离为文字，原图 URL 记入 `备注` |

**17 条异常行不丢弃**，全部导入并标 `数据质量=待确认`，清单如下：

```
[无表格]            ⟨项目02⟩  ⟨客户G⟩
[产品名为空]         ⟨项目07⟩  ⟨客户H⟩-4G+RTK小卡（400张）
[疑似备注]          ⟨项目05⟩  ⟨客户I⟩        「音频」
[疑似备注]          ⟨项目09⟩  ⟨客户J⟩-第二批采购   「📥待补」
[合计行 ×13]        已识别并自动过滤（不进新表）
```

### 3.4 存量关联怎么处理（★ 本方案最大的诚实点）

**结论：存量「产品 ↔ 计划」的对应关系无法全自动重建。**

实测：85/87 个产品行中，只有 **22 条（25%）** 能靠「数量完全相等」自动对上计划。
原因很直白 —— 计划侧的 `生产产品` 是自由文本，与产品行的 `产品名称 + 型号` **字面不对应**：

| 计划.生产产品 | 数量 | 对应的产品行 |
|---|---|---|
| `4G小卡无UWB-v3.1版本` | 1110 | `人员定位卡（4G北斗单频rtk融合蓝牙版本）` ⟨型号C⟩ |
| `物联网卡升级` | 33 | `移动物联网卡 3G/月，3年` ⟨型号D⟩ |
| `2张全功能大卡+PA` | 2 | `全功能大卡+PA` ⟨型号E⟩ |

**因此存量处理策略是「三步走」，而不是「一键迁移」：**

1. **能自动配的 22 条** → 脚本直接建关联
2. **项目内产品数与计划数相等的**（如 ⟨客户K⟩ 1:1、⟨客户L⟩ 3:3）→ 生成**候选配对建议**，人工在界面确认
3. **其余** → `生产计划` 留空，靠**项目级兜底链路**（组 A/组 B）仍能查到「这个项目的全部批次」；随着后续排产逐步补齐

> **这一点必须提前接受**：存量数据的产品级落点会有相当一部分留空。
> 但它不影响新数据 —— 新流程录产品行时当场挂计划，一次就位。

### 3.5 `产品需求` 列的去留（三选一）

| 选项 | 做法 | 代价 | 建议 |
|---|---|---|---|
| **A1** | **原地保留，列名不改** | 出现「两处真相」，需约定「以 `项目产品` 为准，`产品需求` 仅作档案」 | ★ **推荐**，零风险 |
| A2 | 改名为 `产品需求(档案)` | 需同步改 3 处代码（见 3.8） | 可选，更清晰 |
| A3 | 删列 | **会打断微信匹配**（`wx/wxmatch.py` 靠它提品类词） | ❌ 不建议，除非同时改造 wxmatch |

**为什么倾向保留**：`产品需求` 目前是**活的**依赖 —— 微信匹配用它做品类词提取。
保留 = 既有功能零回归；等新流程跑稳一个季度后再决定是否清退。

### 3.6 生产计划侧配套（2 件小事）

1. **拆真堆行 1 条**：`⟨项目06⟩`（`UWB信标 ⟨型号A⟩ ×136；UWB网关 ×2`，数量 138）
   → 拆成 2 行（信标 136 / 网关 2），各挂到 `项目产品` 对应的产品行。
2. **两套冗余关联不动**，但在 `schema.py` 里补注解说明「组 B 的 4 对独有数据已迁入 `项目产品`」，
   避免后人误删。

> 另 2 条看似堆行实为**尾部换行**（`⟨项目03⟩ UWB工卡` 、`⟨项目04⟩ UWB基站`），不需要处理。

### 3.7 界面做法：项目分组视图

`项目产品` 表里建 1 个视图 **`按项目分组`**：

- **分组**：`所属项目`
- **排序**：`所属项目` ↑、`产品编号` ↑
- **显示列**：所属项目 | 产品名称 | 型号 | 数量 | 单位 | 单价 | 金额 | 交付备注 | 生产计划
- **隐藏**：产品编号、来源、数据质量（默认收起）

这样打开就是你要的形态 —— **项目为分组、产品各占一行、每行带自己的计划**。
（SeaTable 的分组视图天然折叠，一个项目一组。）

## 四、备选方案 B：项目表直接拆行（不推荐）

把 `项目` 表 40 行拆成 85 行，一行一个产品，项目级字段重复到每行。

**为什么不推荐**：

| 问题 | 后果 |
|---|---|
| `项目编号` 不再唯一 | 现有 25 列里 `合同`(file)、`合同总价`、`实收`、`待收`、`合同交期` 会重复 85 份 | 
| 破坏 5 条已有 link 列 | `项目.发货清单`、`项目.维修记录`、`项目.项目阶段` 等按「项目一行」设计，拆行后语义崩坏 |
| 项目级聚合全部失效 | `剩余（天）`、`花费天数` 等公式列要全部重写 |
| 不可逆 | 原 40 行结构被改写，回滚困难 |

**唯一场景**：如果坚持「不新增表」，那只能接受上述全部代价。不建议。
