## 第三步：逐维度差异对照（本轮核心）

按下面 **9 个维度**逐条比对你我的做法。每条给出四态结论之一：

> `一致` ｜ `等价但异名` ｜ `冲突` ｜ `单边有`

| # | 维度 | 要对照什么 |
|---|---|---|
| 1 | **实体层** | 业务对象集合与 ID 规则（本侧：12 类对象 + `PREFIX-YYYYMMDD-XXXX`） |
| 2 | **状态机** | 状态集合、合法转移、跳步/回退的严重性；本侧项目主线 14 态 + 2 旁路 |
| 3 | **副作用分级与路由** | 写操作如何分级（本侧 `SIDE` 5 级）、如何分流（本侧 `ρ`） |
| 4 | **授权模型** | 审批→授权、覆盖谓词、次数上限、载荷哈希绑定（本侧 `WriteGrant`/`covers`/`reserve`） |
| 5 | **发布 / 交付门禁** | 什么条件下才允许对外释放（本侧 `G` + `bind` 产物绑定） |
| 6 | **不变量集合** | 你声称的不变量 ←→ 本侧 **G1–G30**，逐条对应；无对应的要明写 |
| 7 | **编号空间** | 你的编号方案 ←→ 本侧 `G*`。⚠️ 本侧**代码里还有一套 `FIX-*` 历史标签**（见 `DEV-KICKOFF.md` §4），别混进来 |
| 8 | **层次归属** | 你的产出属于 `L_gov` / `L_proj` / `L_exec` / 跨层接缝，还是横切多层 |
| 9 | **承载后端** | 本地 / SeaTable / 禅道 / 飞书 / 简道云 / 其它 |

**输出格式**：

```
| 维度 | 你的做法 | 本侧做法 | 结论 | 冲突点 / 待定 |
```

**要求**：`冲突` 必须写清**冲突在哪一句、会导致什么后果**，不许写"有差异"这种没有信息量的话。
每条判断都要给出**文件路径 + 章节号或符号名**，不许凭印象。
